## Maitree font and current artifact

The first rebase used 24,147 bytes of half-resolution A2 font data. The user
reported blurred Thai text, and rejected the subsequent invented pixel shapes
and Sarabun-based redraw. The current candidate uses the original Google Fonts
Maitree ExtraLight outlines, rendered at each native size without thinning or
bitmap enlargement. All 87 Thai characters and eight sizes remain.

Format 5 uses dense six-byte metric records and lossless A1 row/tile encoding.
The descriptor ABI stays 32 bytes, and decoding writes directly into the
caller-owned A8 buffer. Contextual font glyphs and grid-fitted attachments cover
upper vowels, stacked tones, tall stems, lower tails and SARA AM. See the
[font research and shaping evidence](../thai-pixel-font.md).

## Verification and local writer

The companion remains at `c437fdf22b71c7e3c0b9de2b4669d8a4847ce919`.
Exact local pins accept this custom image and same-version stock rollback;
both remain local-only and excluded from direct BLE. Thai cannot stage Case
firmware. The portable companion patch includes the local pin file and tests.

`make check` covers lossless native-font pixel preservation, all characters and sizes,
SARA AM and upper-mark stacking, native placeholder/kerning/register behavior,
odd dimensions and strides, cache failure/eviction/reentrancy, unique anchors,
component preservation and rejection of a checksummed image beyond the flag.
Stock and candidate pass pinned G2Flash validation. Its older ceiling is
overridden only in the offline validator module using the binary evidence
above; the sibling repository remains unchanged.

WebFlasher checks reject payload tampering and unknown pins; 345 companion
tests and its production build pass. The gate ledger records reproduction,
portable-patch and review evidence. Historical 2.2.10.10 instruction reductions
do not establish performance for this Maitree format. No device was contacted
and no firmware was flashed.

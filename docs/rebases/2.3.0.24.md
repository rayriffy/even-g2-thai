# G2 2.3.0.24 rebase evidence

Read when building, reviewing, or preparing a Case-USB transfer of the current
Thai patch. Physical boot, rendering, and rollback remain untested on this
version; the checks here are offline evidence.

## File and installed-address mapping

| Value | 2.2.10.10 | 2.3.0.24 |
| --- | ---: | ---: |
| Main component offset | `0x000BE32D` | `0x000BE36B` |
| Main payload file offset | `0x000BE3AD` | `0x000BE3EB` |
| Main payload size | 3,713,884 | 3,758,720 |
| File delta | `0x00379C33` | `0x00379BF5` |

`file_offset = installed_address - file_delta`; payload byte 32 maps to
`0x00438000` and the Apollo preamble contract is unchanged. The new delta is
odd, so instruction bytes sit at odd file offsets; address-space scans must
step even addresses. Stock programmed end is `0x007CDA60`.

| Role | 2.2.10.10 address | 2.3.0.24 address | Unique exact anchor |
| --- | --- | --- | --- |
| Font-chain builder | `0x00470F6C` | `0x00470B58` | 24 bytes at entry +12 |
| Font-manager call 1 | `0x004718FC` | `0x004714E8` | 24 bytes at call |
| Font-manager call 2 | `0x0047195A` | `0x00471546` | 24 bytes at call |
| Letter-pair helper | `0x00492ED4` | `0x0049333C` | 128 bytes at entry |
| NULL-safe UTF-8 decoder | `0x00492FF6` | `0x0049345E` | 128 bytes at entry |
| Glyph release | `0x004E8D34` | `0x004EA30C` | 32 bytes at entry +32 |
| Glyph descriptor | `0x004E8D90` | `0x004EA368` | 32 bytes at entry |
| LVGL allocator | `0x00458702` | `0x0045855E` | 16 bytes at entry |
| XIP guards (perf fixture) | `0x4760EA`/`0x476100` | `0x475CD6`/`0x475CEC` | 44-byte window, unique |

Region shifts versus 2.2.10.10 differ per area (font manager `-0x414`,
text helper/decoder `+0x468`, glyph routines `+0x15D8`, allocator `-0x1A4`),
so a global shift would have corrupted every hook.

Capstone Thumb disassembly confirms both font-manager calls still target the
stock builder, with unchanged preimages `ff f7 36 fb` and `ff f7 07 fb`.
Their surrounding code stores the returned chain and checks it for NULL.
Exactly two direct BLs target the builder in the whole payload. The five direct letter-helper BL matches are
`0x00493170`, `0x004931F8`, `0x00493BDA`, `0x004A7C78`, and `0x004A7EE2`.

At `0x00493348` (helper entry +12), the stock helper's PC-relative load
resolves to the literal pool at `0x004936AC` — note the pool moved
differently (`+0x1468`) than the code around it, so the old slot address plus
the region shift is wrong and was not used. That literal contains
`0x007C8120`, whose word is decoder Thumb entry `0x0049345F`. The wrapper
follows both indirections. The decoder prologue still substitutes its stack
slot for a NULL offset (`cmp r1,#0; bne; mov r1,sp`). The artifact emulation
tests exercise ASCII, Thai and NULL-offset decoding through this real new
stock decoder.

The allocator retains its size argument, mutex acquire/release (`0x00442F90`/
`0x00442FF6`) and returned allocation behavior. Its stock allocation delegate
is now `0x0049CDAE`. The glyph-descriptor routine still clears `0x20` bytes
and follows fallback word `0x1C`; glyph release still reads cache-entry word
`0x1C` and the callback at font offset 8. The IAR descriptor ABI and bounded
SRAM cache remain intact.

Final-image disassembly confirms both font hooks BL to `0x007CEAC0` (the chain
wrapper), the letter helper B.W to `0x007CE4E0`, and the glyph-descriptor
entry B.W to `0x007CE660`. The chain wrapper constructs `0x00470B59`
(`movw r2,#0xb59; movt r2,#0x47`) and `BLX r2`; the text wrapper constructs
`0x004936AC` (`movw r2,#0x36ac; movt r2,#0x49`), loads the storage pointer,
NULL-checks it, and substitutes `sp` for a NULL offset argument. The lookup
wrapper trampoline is at `0x007CE660`. The font blob is unchanged from the
previous patch. Strict stock SHA-256 and hook preimages gate patch generation;
headroom is tight (2,382 bytes) but the patch refuses output beyond the
ceiling.

Performance evidence in [Thai performance](../thai-performance.md) was
measured on the 2.2.10.10 artifact; the injected logic is unchanged and the
lookup/bitmap hook addresses above are the 2.3.0.24 equivalents.

## Companion and verification

The vendored companion stays at `c437fdf22b71c7e3c0b9de2b4669d8a4847ce919`.
Its local patch pins **both** the Thai artifact and matching stock rollback
bundle independently of the hosted catalog. Stock rollback is classified as
official; Thai is classified as local custom. Both require exact whole-file
and main hashes. Thai cannot stage Case firmware; both local-only targets
remain blocked from direct BLE transfer.

Offline checks:

- `make check`: 51 tests, no unexpected skips, including the 2.3.0.24
  mapping, anchor uniqueness, component preservation, corrupted-stock
  rejection and existing emulation suites.
- Independent pinned `g2flash.validate_firmware`: both stock and patched
  bundles pass six-component validation and Apollo bounds/checksums.
- `make webflasher`: exact bundle and main pin match.
- `node tools/check_webflasher_artifacts.mjs`: both real files accepted by
  parser/final writer gate; altered payloads and unknown bundle pins rejected.
- Component identity: codec, BLE, touch, Case and bootloader payloads
  byte-identical between stock and patched.
- No Case or temple was connected during any of these checks.

See [`../flashing.md`](../flashing.md) for manual selection and one-temple
testing. Do not use the vendored companion's catalog for this version's
rollback.
